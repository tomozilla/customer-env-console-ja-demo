# customer-env-console-ja-demo

[English](README.md) | 日本語

**顧客ごとにSupabaseプロジェクトを分ける**運用の、小さな学習用デモです。全プロジェクトに流すSQLのテンプレート、プロジェクトがテンプレートのままかを調べる**スキーマの指紋**のSQL、顧客プロジェクトの台帳を読んで「最新／古い／手で変更」を示す静的なコンソール。

> **個人の学習記録・非公式です。** 顧客名はすべて架空です。ページはどのプロジェクトにも接続しません。指紋のSQLは自分で実行し、結果を台帳に貼ります。

Qiitaの2本の記事のコードです：手順編（テンプレート・指紋・引き渡し・費用）と、コンソールをつくったWebアプリ編。

英語版が基本で、日本語コメント・UIのコピーは [`ja/`](ja/) にあります。

## ファイル

| ファイル | 内容 |

| `app/test.js`, `app/package.json` | 15項目のテスト |
| `sample/registry.sample.json` | 架空の台帳（指紋は、私のテストで実際に取った値） |

## 動かし方

```bash
# SQL：各プロジェクトのSQLエディタに sql/01_template_v1.sql、続けて sql/10_fingerprint.sql

python3 -m http.server 8000
# http://localhost:8000/ja/app/ （英語版は /app/）を開く
node app/test.js
```

## セキュリティ上の注意

- テンプレートの例のポリシー（「ログインしていれば誰でも読み書き」）は、**1プロジェクト＝1顧客**だから成り立ちます。共有のプロジェクトなら、顧客IDで絞るRLSが必要です。
- `portal.template_meta` は、意図的にRLS有効・ポリシーなしです。
- 指紋はメタデータだけを読みます。顧客のデータは見ません。

## 確認したこと（2026-10-27）／していないこと

- 確認：無料の2プロジェクトで、v1を流すと**同じ指紋**／手で列を足すと指紋が変わる／片方にv2を流すと別の（想定どおりの）指紋／クリーンなコピーでのコンソールと `node app/test.js`。
- 未確認：CLIのマイグレーションでの配布、顧客の組織への実際の引き渡し、ロール（Team）、数件を超える運用、スマホ幅。
